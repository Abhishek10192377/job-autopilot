# Job Autopilot

A personal job-search assistant that runs on your own computer. It finds software-development jobs from sources that permit automated access, scores each one against your resume, prepares truthful application materials, and tracks every application. You stay in control of what gets submitted.

## What it does

- **Discovers jobs** from public job APIs, RSS feeds and company career boards (see [Job sources](#job-sources)).
- **Scores every job out of 100** against your profile: technical skills 35, relevant experience 25, role 20, location and work arrangement 10, other requirements 10. Information a posting does not publish is marked *unknown* and given half credit, never assumed.
- **Prepares an application pack** per job: tailored resume (PDF and DOCX), professional summary, cover letter, email draft, recruiter note, LinkedIn connection note and answers to standard questions.
- **Helps you apply**: opens the official page, prefills supported forms in a browser you watch, or emails the application when the posting asks for email applications.
- **Tracks applications** through Discovered → Matched → Saved → Prepared → Awaiting approval → Applied → Interview → Offer / Rejected, with follow-up reminders and duplicate prevention.

## Quick start

Requirements: Node.js 20 or newer, and MongoDB (a local MongoDB Community Server, or a MongoDB Atlas connection string).

```bash
npm install

# 1. Create .env.local and store a copy of your resume
npm run setup -- --resume "C:\path\to\your-resume.pdf"

# 2. Choose the dashboard password (only its hash is stored)
npm run set-password -- "a password of at least 10 characters"

# 3. Make sure MongoDB is running (the MongoDB Windows service, or Atlas via MONGODB_URI)

# 4. Start the dashboard
npm run dev

# 5. In a second terminal (optional): start the background worker
npm run worker
```

Open http://localhost:3100, sign in, and press **Find jobs now**.

The worker is only needed for scheduled discovery, AI scoring of new jobs, follow-up reminders and automatic mode. Everything else works from the dashboard alone.

## Configuration

Everything secret lives in `.env.local`, which is git-ignored. `.env.example` lists every variable with placeholder values.

| Variable | Needed for | Notes |
| --- | --- | --- |
| `MONGODB_URI` | Always | For example `mongodb://127.0.0.1:27017/job_autopilot` |
| `AUTH_SECRET` | Always | Generated by `npm run setup` |
| `DASHBOARD_PASSWORD_HASH` | Always | Written by `npm run set-password` |
| `OLLAMA_URL`, `OLLAMA_MODEL` | AI match analysis and AI-tailored letters (local Ollama) | For example `http://localhost:11434` and `qwen2.5:7b`. Without them a built-in rule-based engine does the scoring and writing |
| `ADZUNA_APP_ID`, `ADZUNA_APP_KEY` | Adzuna source (Indian city searches) | Free key from developer.adzuna.com |
| `RAPIDAPI_KEY` | JSearch source | Subscribe to JSearch on RapidAPI |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | Email applications and emailed reminders | For Gmail, use an app password |
| `BROWSER_CHANNEL` | Assisted autofill | `msedge` or `chrome` (an installed browser is used; nothing is downloaded) |

Preferences (titles, cities, minimum score, maximum experience, salary floor, employment type, daily limit, review mode, reminders, sources) are set on the **Settings** page.

## Job sources

| Source | Access | Credentials |
| --- | --- | --- |
| Remotive, Remote OK, Jobicy, Himalayas, Arbeitnow | Public job APIs | None |
| We Work Remotely | Public RSS feeds (robots.txt checked first) | None |
| Greenhouse, Lever, Ashby company boards | Official public job-board APIs | None. Edit the company list in Settings |
| Adzuna (India) | Official search API | `ADZUNA_APP_ID`, `ADZUNA_APP_KEY` |
| JSearch | Licensed aggregator API | `RAPIDAPI_KEY` |

Each source is fetched at most once every 6–12 hours, with a delay between requests and an identifying user agent. Listings link back to the original posting and credit the source.

**LinkedIn, Indeed, Naukri, Instahyre, Wellfound and Cutshort are not fetched or automated.** None offers an API a job-seeker may use, and their terms prohibit scraping and automated activity; automating them risks your account. Use **Jobs → Add job manually** to paste a posting from those sites: it is scored, gets tailored materials and is tracked like any other job, and you apply on the site yourself. Adzuna and JSearch are the permitted way to see more India-based listings.

## How applying works

| Where the job is applied for | What the assistant does |
| --- | --- |
| Greenhouse, Lever or Ashby form | **Open and prefill form** opens a visible browser, fills the fields it has verified answers for (name, email, phone, LinkedIn, GitHub, current company) and attaches the tailored resume. You review and press Submit. |
| Posting asks for applications by email | Sends the email from your own mailbox with the resume attached, after you confirm. In automatic mode it may send without a click when every check passes. |
| Job portals and other company sites | Opens the page and gives you the prepared materials to copy. Nothing is automated. |

Automatic submission of web forms is not offered: the submission APIs of Greenhouse, Lever and Ashby are only available to the employer.

The assistant never clicks Submit on a form, never touches a CAPTCHA, and never answers personal declarations (work authorisation, visa sponsorship, salary, notice period, relocation, gender, ethnicity, disability, veteran status, consent boxes). Those, and any required question without a verified answer in your profile, are listed for you to complete.

**Automatic mode** (Settings → Application review mode) sends an email application only when all of these hold: the posting invites email applications, SMTP is configured, the job meets your eligibility criteria, the materials have no unresolved review notes, your name, email and phone are verified, it is not a duplicate, and the daily limit is not reached. Otherwise the application waits under *Awaiting approval* with the reasons shown.

**Stop all automation** in the top bar halts discovery, autofill and sending immediately and cancels queued work.

## Truthfulness

- `seed/profile.json` was transcribed from your resume and is loaded into the database on first use. Edit it afterwards on the **Profile** page, which also compares the profile with the stored resume file and lists any differences.
- Tailoring reorders your resume's own bullet points; it never rewrites them.
- Every generated or edited text is checked against the profile. Technologies not on your resume, more years of experience than your dates support, figures that are not on your resume, and unheld degrees or certifications are flagged; an AI draft that fails the check is replaced by the fact-only template.
- Experience is calculated from your employment dates on the day a document is generated.
- The original resume is stored unchanged. Each tailored version is saved as a separate file under `data/private/resumes/<job>/` and never overwritten.

## Duplicate prevention

- One listing per normalised URL (tracking parameters, fragments and trailing slashes removed).
- One listing per normalised company + title, so the same role on two boards is stored once with both links. When a role is listed once per office, the best-fitting listing is kept.
- Marking a job as applied is refused if you already applied to the same role through another listing, and an application email can never be sent twice.

## Security

- The dashboard requires a password; sessions are signed, HTTP-only cookies. Login attempts are rate-limited and cross-site requests to the API are refused.
- API keys and SMTP credentials are read from the environment on the server only.
- `.env.local`, `data/private/` are git-ignored. Check `git status` before your first commit.

## Deployment

The app is designed to run on your own machine: assisted autofill opens a browser on the computer where the server runs, and your resume and generated documents are stored on its disk.

To run it on a server instead (for discovery, scoring, documents and tracking):

1. Use MongoDB Atlas and set `MONGODB_URI`.
2. Set `AUTH_SECRET`, `DASHBOARD_PASSWORD_HASH` and any optional keys as environment variables.
3. Run `npm run build`, then `npm run start` for the dashboard and `npm run worker` as a second long-running process.
4. Serve it over HTTPS, and mount persistent storage at `data/private` (or set `DATA_DIR`).

Serverless hosts are not a good fit: the worker must run continuously and generated files need a persistent disk. Assisted autofill should be turned off in Settings on a server.

## Troubleshooting

- **“Cannot reach MongoDB”** — make sure the MongoDB service is running, or check `MONGODB_URI`.
- **“The dashboard password is not set up yet”** — run `npm run set-password -- "…"` and restart the server.
- **A source shows “Failed”** on the Settings page — the reason is shown there; other sources are unaffected. A company board that no longer exists should be removed from its list.
- **Few matches** — the daily discovery limit keeps the best-scoring new jobs each day, so results build up over several days. Add Adzuna or JSearch keys for India-based listings, add companies you like to the board lists, or lower the minimum score.
